WorldView codebook simplification
================================

This migration makes processed numeric values the single authoritative coding
shown in the Codebook and used by WorldView.

It DOES NOT change the underlying browser dataset, so existing model results
and validation fixtures remain unchanged.

Canonical binary coding
-----------------------
Q165-Q168   0 = No; 1 = Yes
Q260        0 = Female; 1 = Male
Q263        0 = Immigrant to this country; 1 = Born in this country

Q263 is renamed to:
  Respondent immigrant status

This neutral label avoids implying that 1 must mean immigrant while preserving
the existing numerical data.

Codebook page
-------------
The expanded variable card is simplified to:
- Question / description
- Topic
- Variable type
- Processed values
- Missing-data treatment

The duplicated user-facing fields are removed:
- Display type
- Correlation use
- Correlation coding
- Valid/missing counts
- Generic interpretation boilerplate

Processed categorical values are shown as:
  Value | Label

The Value column is the actual processed value used by WorldView.

Apply
-----
1. Extract this ZIP.
2. Copy apply_codebook_simplification.R into the ROOT of your WorldView repo.
3. In RStudio, with the repo as the working directory, run:

   source("apply_codebook_simplification.R")

4. Serve:
   servr::httd("worldview_deployment")

5. Hard refresh with Ctrl+F5.

Files modified by the script
----------------------------
worldview_deployment/data/worldview-codebook-v1.0.0.json
worldview_deployment/assets/app.js
R/worldview_build.R

No data rebuild is required.

Testing
-------
Check Q165-Q168, Q260 and Q263 in the Codebook.
Then check Summary, Visualisations and Models to confirm existing results are
unchanged, and run /validation.html.
